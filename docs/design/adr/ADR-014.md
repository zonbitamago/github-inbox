# ADR-014: 開発とビルドは electron-vite、配布物は electron-builder で作り、Mac 用は両対応の1つにする

## ステータス

採用（2026-11-26 技術者が判断し、文面をレビューして確定）

## コンテキスト

- Electron + React + TypeScript で作る（ADR-003）。配布物は electron-builder で、Mac は DMG、Windows は利用者ごとのインストーラー（ADR-008）
- コードはメイン・preload・画面の3つに分かれ、`src/main`・`src/preload`・`src/renderer` に置く（component-backend.md 3.、component-frontend.md 7.）
- 対応は macOS 13 以降の Apple Silicon と Intel、Windows 10・11 の64bit（C-07）
- 手順書を見なくても入れられるようにする（D-024）

## 決定

- 開発とビルドは **electron-vite** を使う。メイン・preload・画面を Vite でまとめてビルドし、開発中は画面の変更をすぐ反映させる
- 配布物は **electron-builder** で作る（ADR-008）。electron-vite の出力（`out/`）を入れる
- Mac 用の DMG は、**Apple Silicon と Intel の両対応の1つ**（universal）にする
- 設定の素案は build-and-release.md 2.

## 理由

- electron-vite は electron-builder と組み合わせるのが一般的で、⑩ で決めた3つのフォルダの形とそのまま合う
- 両対応の1つなら、利用者が自分の Mac に合うものを選ばずに済み、手順書を見なくても入れられる（D-024）

## 検討した代替案

### 代替案A: Electron Forge

- メリット: Electron の公式の道具
- 採用しなかった理由: 配布物を作る仕組みを自前で持ち、electron-builder（ADR-008）と役割が重なる

### 代替案B: Vite と tsc を自前で組む

- メリット: 道具を増やさない
- 採用しなかった理由: 3つのビルドと、開発中の立ち上げ・画面の即時反映を自分で組む手間がある

### 代替案C: Mac 用を Apple Silicon 用と Intel 用に分ける

- メリット: 1つずつの大きさが約半分
- 採用しなかった理由: 利用者が選ぶ必要があり、間違えると動かない・重い。手順書を見ずに入れる形と合わない

## 結果（トレードオフ）

- ✓ 3つのフォルダの形のまま、開発とビルドがまとまる
- ✓ Mac の利用者は1つの DMG を入れるだけでよい
- ✗ 両対応の DMG は、片方だけのものの約2倍の大きさになる
- ✗ electron-vite・electron-builder の版を、Electron の版に合わせて上げ続ける必要がある（Q-12）
