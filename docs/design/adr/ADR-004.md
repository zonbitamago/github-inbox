# ADR-004: 認証は OAuth App のデバイスフローを既定にし、classic PAT の貼り付けも選べる。トークンは safeStorage で暗号化して保存する

## ステータス

採用（2026-11-26 技術者が判断し、文面をレビューして確定。試作の結果を「結果」に反映）

## コンテキスト

- 通知 API は classic のトークンでしか使えず、スコープは `notifications` と `repo` が要る（ADR-002）
- 利用者が自分の GitHub アカウントで認証して使い始められる（F-27）。希望者が手順書を見ずに、アプリの案内だけで使い始められる（F-36・AC-29）
- 認証情報を平文のファイルや URL に置かない（N-05）。github-prs はトークンを URL で渡しており、履歴に残る問題があった
- Organization の管理者の承認は要らない（C-02）。SAML SSO は使っていない（D-019）

## 決定

- 既定の認証は OAuth App のデバイスフローにする。アプリが表示するコードを、利用者がブラウザの GitHub の画面に入れて認可する。OAuth App は依頼者が個人アカウントで1つ登録し、デバイスフローを有効にする。アプリには client ID だけを入れ、client secret は使わない
- OAuth App を使えない人のために、利用者が作った classic PAT（`notifications`・`repo` スコープ）を貼り付ける方法も選べるようにする
- 受け取ったトークンは、Electron の safeStorage（Mac はキーチェーン、Windows は DPAPI）で暗号化してから手元に保存する。画面（レンダラー）には渡さない（ADR-007）

## 理由

- デバイスフローは、利用者がスコープを選んだりトークンを作ったりする必要がなく、アプリの案内だけで使い始めやすい（AC-29）
- デバイスフローは client secret を使わないため、公開リポジトリ（ADR-005）に client ID を置いても問題がない
- OAuth App の登録に Organization の管理者の操作は要らない（C-02）
- PAT の貼り付けを残しておけば、OAuth App が使えない事情があっても使い始められる
- safeStorage は OS の保管の仕組みで暗号化するため、平文で置かない（N-05）を満たせる

## 検討した代替案

### 代替案A: classic PAT の貼り付けだけにする

- メリット: OAuth App の登録が要らない
- 採用しなかった理由: 利用者がスコープを選んでトークンを作る手間と、期限切れへの対応が要り、アプリの案内だけで使い始めるのが難しくなる。PAT は補助の方法として残す

### 代替案B: gh CLI のトークンを使う

- メリット: 認証の画面を作らなくてよい
- 採用しなかった理由: gh を入れてログインしている人に限られる。チームの希望者全員には前提にできない

### 代替案C: OAuth App の Web フロー（ローカルでリダイレクトを受ける）

- メリット: 利用者がコードを入れる手間が無い
- 採用しなかった理由: client secret が要り、公開リポジトリに置けない。手元で受け口を開く仕組みも要る

## 結果（トレードオフ）

- ✓ 利用者はブラウザでコードを入れるだけで使い始められる
- ✓ トークンは暗号化して保存され、画面側には出ない
- ✗ OAuth App の認可画面では、`repo` スコープが「プライベートリポジトリの完全な制御」と表示される。アプリは書き込まないことを、認証の前にアプリの画面で説明する（F-36）
- ✗ PAT を使う人は、期限切れのときに貼り直しが要る。期限切れは「受け取れていない」表示（N-08）で知らせる
- ✗ 署名しないため、Mac では**新しい版を入れ直すたびに、キーチェーンへのアクセスを求めるダイアログが1回出る**（試作で確認。許可すれば読める）。技術者がこれを受け入れた（D-022）。新しい版の初回起動のとき、確認が出る前にアプリで案内する（F-36・AC-42）
- ✓ safeStorage で暗号化したファイルに平文が含まれないことを試作で確かめた
- 実装の注意: Electron 45 では safeStorage の同期版の関数（`encryptString` など）が非推奨。非同期版（`encryptStringAsync` など）を使う
- ✗ OAuth App の持ち主は依頼者の個人アカウントになる。依頼者が登録を消すと、全員が認証し直しになる
- ✗ Organization で OAuth App のアクセス制限が有効だと、管理者の承認なしでは会社のプライベートリポジトリを読めない（C-02 の前提が崩れる）。⑬ の最初に確かめ、読めなければ classic PAT を既定にする（auth-flow.md 7.。⑫ の DR-08 で追記）
