# ADR-013: AI エージェントは Claude Code を主に使い、ルールの正は AGENTS.md に置く

## ステータス

採用（AI の提案を、2026-11-26 に技術者がレビューして確定）

## コンテキスト

- 開発は1人＋AI 1体の直列（D-002）。これまでの要件定義・設計は Claude Code で進めてきた
- 設計フレーム ⑪ は、採用するエージェントを ADR に残すことを求めている
- 要件定義の段階で、AGENTS.md（エージェントを問わないルール）と、それを読み込むだけの CLAUDE.md を置いた
- 判定の処理（`src/main/core/`）と共有の契約（`src/shared/`）は、AI が実装中に勝手に変えてはいけない範囲（domain-model.md 7.・8.）

## 決定

- 主に使うエージェントは Claude Code
- ルールの正は、ルートの `AGENTS.md` に置く。ルートの `CLAUDE.md` は `AGENTS.md` を読み込み、Claude Code だけに要る補足を足す
- 守る範囲が特にあるフォルダには、フォルダ別の `CLAUDE.md` を置く: `src/main/core/CLAUDE.md`（判定と不変条件）、`src/shared/CLAUDE.md`（契約）
- 規約の中身は `docs/design/conventions/` に置き、AGENTS.md からはそこを指す（AGENTS.md に中身を重ねて書かない）

## 理由

- これまでの進め方と道具を変えずに済む
- AGENTS.md を正にしておけば、ほかのエージェントを使うことになっても、ルールを書き直さずに済む
- フォルダ別の CLAUDE.md は、そのフォルダのファイルを触るときに Claude Code が読み込むため、守る範囲の決まりを確実に渡せる

## 検討した代替案

### 代替案A: CLAUDE.md だけに書く

- メリット: ファイルが1つで済む
- 採用しなかった理由: ほかのエージェントに切り替えると、ルールを移し替える必要がある。要件定義で既に AGENTS.md を正にしている

### 代替案B: フォルダ別のファイルを置かず、AGENTS.md にすべて書く

- メリット: 1か所で読める
- 採用しなかった理由: AGENTS.md が長くなり、全部の作業で毎回読む量が増える。守る範囲の決まりは、そのフォルダを触るときに読めれば足りる

## 結果（トレードオフ）

- ✓ ルールの正が1つで、エージェントを替えても使える
- ✓ 守る範囲の決まりが、そのフォルダを触るときに確実に読まれる
- ✗ フォルダ別の CLAUDE.md は Claude Code に固有の仕組み。ほかのエージェントでは読まれないため、AGENTS.md にも「どのフォルダに決まりがあるか」を書いておく
