# ADR-006: 受け取った出来事と設定を手元に保存し、GitHub からは差分だけ取る

## ステータス

採用（2026-11-26 技術者が判断し、文面をレビューして確定）

## コンテキスト

- 立ち上がっていなかった間の出来事を、次に立ち上げたとき一覧に出す。出来事の一覧の日数（1〜30日、既定7日）まで遡る（F-06・F-32）
- 出来事は1件のコメント・レビュー・依頼ごとに数える（D-011）。GitHub の通知はスレッド単位にまとまるため、1件ずつにするには追加の問い合わせが要る（ADR-002）
- GitHub の利用制限にかからない（N-04）。各自の利用制限は1時間あたり5,000回で、同じアカウントの他の道具と共有する（ADR-001）
- 設定（デスクトップ通知のオン／オフ、期間、出来事の一覧の日数、並べ方、自動起動、言語）を残す必要がある（F-09・F-16・F-25・F-26・F-32・F-33）

## 決定

- 受け取った出来事と設定を、利用者の PC の中に保存する
- 立ち上げたときと受け取りの途中は、前回からの差分だけを GitHub から取る（通知 API の `since` と `If-Modified-Since` を使う。⑬ で `If-None-Match`（ETag）に変えた。CR-003）
- 保存する出来事は、出来事の一覧の日数の上限（30日）より古いものから消す
- 保存の形式（SQLite・JSON など）と、出来事の識別子は ⑩.1・⑩.2 で決める

## 理由

- 立ち上げのたびに最大30日分の出来事を1件ずつ取り直すと、問い合わせが多くなり、一覧が出るまで時間がかかる
- 差分だけを取れば、利用制限（N-04）と立ち上がりの速さの両方に効く
- 設定はどちらにしても保存が要るため、同じ仕組みに載せられる

## 検討した代替案

### 代替案A: 設定だけ保存し、出来事は立ち上げるたびに取り直す

- メリット: 保存の仕組みが簡単で、手元のデータと GitHub が食い違わない
- 採用しなかった理由: 立ち上げのたびに最大30日分を取り直すため、問い合わせが増え、立ち上がりが遅くなる

## 結果（トレードオフ）

- ✓ 問い合わせが少なく、立ち上がりが速い
- ✓ ネットワークが切れても、保存済みの出来事は一覧に出せる
- ✗ 保存の仕組み（形式、古いものの削除、壊れたときの扱い）を作る必要がある
- ✗ 出来事の中身（コメントの抜粋など）が PC の中に残る。会社のプライベートリポジトリの内容を含むため、保存場所と扱いを ⑨ で確かめる
