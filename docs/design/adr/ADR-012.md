# ADR-012: 画面の状態は React 標準の仕組み（useSyncExternalStore）で持ち、状態管理の部品を入れない

## ステータス

採用（2026-11-26 技術者が判断し、文面をレビューして確定）

## コンテキスト

- 画面が出すもの（出来事・PR の一覧・受け取りの状態・設定）は、すべてメインプロセスが持ち、IPC で画面に知らせる（ADR-007、ipc-contract.md）
- 画面の数は少ない（メイン・設定・使い始めの案内・キーチェーンの案内。component-frontend.md）
- 画面は GitHub に直接問い合わせない

## 決定

- 画面側に、メインからの知らせを受けて持つ小さな store を1つ作り、部品は React の `useSyncExternalStore` で読む
- 画面からは store を書き換えない。変えるときは IPC で頼み、知らせで戻ってきた値を出す
- 入力中の値や画面の中だけの状態は、各部品の `useState`・`useReducer` で持つ
- 状態管理の部品（Zustand・TanStack Query など）は入れない

## 理由

- 状態の出どころがメインプロセス1つで、画面の数も少ないため、標準の仕組みで足りる
- 部品が増えない
- TanStack Query は、画面からサーバーに問い合わせる形に向いた部品で、知らせを受ける形が中心の今回は利点が小さい

## 検討した代替案

### 代替案A: Zustand

- メリット: 書き方がそろいやすく、選んで読む仕組みがある
- 採用しなかった理由: 部品が1つ増える。今の規模では標準の仕組みとの差が小さい

### 代替案B: TanStack Query

- メリット: 問い合わせの結果の保持・読み直し・読み込み中の扱いがそろっている
- 採用しなかった理由: 画面から問い合わせる形向けで、メインからの知らせが中心の今回は合わない

## 結果（トレードオフ）

- ✓ 部品が増えない
- ✓ 状態の持ち主がはっきりする（メインが正、画面は写し）
- ✗ store と、選んで読むための小さな関数を自前で書く。画面が増えて扱いにくくなったら、代替案A を考える
