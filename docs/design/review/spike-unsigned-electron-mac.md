# 試作の記録: 署名しない Electron アプリの振る舞い（Mac）

- 実施: 2026-11-26（⑧ と ⑨ の間。D-021）
- 目的: ADR-003（Electron）・ADR-004（safeStorage）の前提を、署名しない状態（C-03）で確かめる。requirements.md 5. #5、container-overview.md 5. のリスク
- 範囲: この PC（Mac）だけ。**Windows は確かめていない**（D-021）
- 試作のコード: 使い捨て。リポジトリには入れず、作業用の一時フォルダに置いた（Electron 45.4.1、electron-builder 26.18.0）

## 1. 環境

| 項目 | 値 |
| --- | --- |
| Mac | Apple Silicon（arm64）、macOS 26.7.3 |
| ビルド | `electron-builder --mac dir --arm64`、`mac.identity: "-"`（ad-hoc 署名。実質的に署名なし） |
| 画面の設定 | contextIsolation 有効、nodeIntegration 無効、sandbox 有効（ADR-007） |
| 比べたビルド | v0.0.1 と v0.0.2（版だけ変えて再ビルド。署名のハッシュが変わる） |

## 2. 自動で確かめた結果

| 確かめたこと | 結果 | 補足 |
| --- | --- | --- |
| 署名 | ad-hoc（`Signature=adhoc`、Hardened Runtime 付き） | Hardened Runtime と ad-hoc の組み合わせで起動に失敗しうるという警告がビルド時に出たが、起動はできた |
| Gatekeeper の判定（`spctl`） | rejected | 想定どおり。ダウンロードした配布物を開くと警告が出る |
| デスクトップ通知が使えるか（`Notification.isSupported()`） | true | 実際に出るかは手で確かめる（3.） |
| safeStorage が使えるか | true。暗号化して復号できた | **Electron 45 では同期版の関数（`encryptString` など）が非推奨**。非同期版（`encryptStringAsync` など）を使う |
| ログイン項目の状態（初期） | `status: not-found` | macOS 13 以降の仕組み（SMAppService）の状態が返る |
| 2つのビルドの署名のハッシュ | v0.0.1 と v0.0.2 で異なる | キーチェーンのアクセス権は署名に結び付くため、版を上げたときの振る舞いを手で確かめる |

## 3. 手で確かめた結果

技術者が画面を見て確かめた。

| # | 手順 | 結果 |
| --- | --- | --- |
| 1 | 「デスクトップ通知を出す」を押し、別のアプリを前面にしてから通知をクリックする | **一時フォルダから開いたときは失敗**。許可も求められず、`Notifications are not allowed for this application` になった（Electron の `failed` イベントが Mac でも出た）。OS のログには、アプリの登録情報を引けない（エラー -10814）とあった。**`~/Applications` に置いて開き直すと、許可を求められずに通知が出て、クリックするとアプリが前面に出た** |
| 2 | 別のアプリに移ってから、Cmd+Tab と AltTab アプリで戻る | OK（どちらでも戻れた） |
| 3 | 自動起動をオンにし、ログの `status` とシステム設定を見る。オフに戻す | OK。オンで `status: enabled`、システム設定に出た。オフで `status: not-registered` になり、ログイン項目から外れた（最初の確認ではオフにした後もログイン項目に残っていたが、別の場所に置いたコピーで操作したためと考えられる。`~/Applications` に置いたもので外れることを確かめた） |
| 4 | ダミーの文字列を暗号化して保存し、読み出す | OK。保存したファイルに平文は含まれず（`plaintextFoundInFile: false`）、読み出せた |
| 5 | ウィンドウを閉じる | OK。アプリが終了し、Cmd+Tab から消えた |
| 6 | 版を上げたビルド（v0.0.2）で、v0.0.1 が保存したものを読み出す | **キーチェーンへのアクセスを求めるダイアログが出た**。許可すると読み出せた |
| 7 | ダウンロードした状態（quarantine 属性付き）のコピーを開く | 「“GitHubInboxSpike.app” は開いていません。Apple は、“GitHubInboxSpike.app” に Mac に損害を与えたり、プライバシーを侵害する可能性のあるマルウェアが含まれていないことを検証できませんでした。」と出た（ボタンは「ゴミ箱に入れる」「完了」）。「完了」を押した後、システム設定の「プライバシーとセキュリティ」で「このまま開く」を押すと開けた |

## 4. 分かったことと設計への反映

| # | 分かったこと | 反映先 |
| --- | --- | --- |
| 1 | 署名しない（ad-hoc 署名の）Electron アプリでも、Mac ではデスクトップ通知・クリックで前面・切り替え・自動起動・safeStorage・閉じたら終了が動く。**ADR-003（Electron）の前提は Mac では崩れていない** | ADR-003 |
| 2 | デスクトップ通知は、アプリが OS に登録された場所（アプリケーションフォルダ）にあることが前提。一時フォルダ（やダウンロードしたままの場所）から開くと、許可も求められずに失敗する | 手順書（F-30）に「アプリケーションフォルダに移してから開く」を入れる（D-022）。開発中にデスクトップ通知を確かめるときも、アプリケーションフォルダに置いたビルドで確かめる（⑪） |
| 3 | デスクトップ通知に失敗すると、Electron は `failed` イベントを出す（Mac でも出た）。何もしなければ、利用者は気づけない | 失敗を画面で知らせるかを依頼者に確かめる（AI案。N-08 の範囲を広げる案） |
| 4 | 版を上げると、キーチェーンへのアクセスを求めるダイアログが出る（署名のハッシュが変わるため）。許可すれば読める | ADR-004 のトレードオフとして受け入れるかを技術者が判断する。受け入れる場合は手順書（F-30）で案内する |
| 5 | ダウンロードした配布物は、Gatekeeper の警告の後、「プライバシーとセキュリティ」の「このまま開く」で開ける | 手順書（F-30）に文言と操作を載せる |
| 6 | Electron 45 では safeStorage の同期版の関数が非推奨 | 非同期版を使う（⑩.2・ADR-004） |
| 7 | ad-hoc 署名と Hardened Runtime の組み合わせで起動に失敗しうるという警告がビルド時に出た（今回は起動できた） | 配布物を作る設定（⑪）で、Hardened Runtime を切るか、必要な entitlement を足すかを決める → ⑪ で入れたままにすることにした（トークンの保護のため。build-and-release.md 2.） |
| 8 | **Windows は確かめていない** | ⑫ のリスク登録簿に残す。Windows の利用者に配る前に確かめる（D-021） |

> 2026-11-26 追記: 上の「手順書（F-30）に入れる」としたものは、D-024 でアプリの初回の案内（F-36）に移した。初回の OS の警告の越え方だけは、配布ページの短い説明（F-30）に載せる。

## 5. 片付け

`~/Applications` に置いた試作アプリ、設定フォルダ（`~/Library/Application Support/GitHubInboxSpike`）、キーチェーンの項目（`GitHubInboxSpike Safe Storage`）は削除した。システム設定の「通知」の一覧に試作アプリが残っている場合は、消してかまわない。
