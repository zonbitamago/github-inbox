## 2. 区分値

### 2.1 出来事の種類

| コード | 業務語 | 定義 | 対象 |
| --- | --- | --- | --- |
| `review_requested` | レビュー依頼 | 利用者に PR のレビューが依頼された | PR |
| `review` | レビュー | 利用者が作った PR にレビューが付いた。結果は 2.2 | 自分が作った PR |
| `comment` | コメント | 利用者が作った PR にコメントが付いた | 自分が作った PR |
| `ci` | CI の結果 | 利用者が起動した GitHub Actions のワークフローが完了した。結果は 2.3（D-008） | ワークフロー（PR に紐づくことが多い） |
| `mention` | メンション | PR・issue の本文やコメントで、利用者が @ で名指しされた。利用者が所属する GitHub のチームが @ でメンションされた場合も含める（D-020）。GitHub Discussions でのメンションは C（あれば） | PR・issue（Discussions は C） |
| `assign` | アサイン | PR・issue の担当者に利用者が割り当てられた | PR・issue |
| `participating` | 参加中の PR への発言 | 参加中の PR（利用者がレビュー・コメントした、他人が作った open の PR）に、他の人が新しいコメント・レビューを付けた。@ で名指しされていなくても対象 | 参加中の PR |

- `review_requested` には、利用者が所属する GitHub のチームに来たレビュー依頼（チーム宛て）も含める。優先度は S（できれば）
- 根拠: 反応して動いていた通知（hearing-memo.md 3.）と、③ の判断（D-012）。Slack 連携の個人向け通知のうち、デプロイのレビュー依頼は選ばれていないため含めない
- **利用者自身の操作は出来事にしない**（例: 自分の PR に自分でコメントした）。④ で AI が補った規則で、依頼者が確認済み（acceptance.md AC-08）
- **bot の発言も出来事にする**。bot は、GitHub がアカウントの種類を Bot としているもの（Dependabot、GitHub Actions、Copilot など）。bot の発言だけデスクトップ通知をオフにできる（D-014）

### 2.2 レビューの結果

| コード | 業務語 | GitHub の値 |
| --- | --- | --- |
| `approved` | 承認 | APPROVED |
| `changes_requested` | 修正依頼 | CHANGES_REQUESTED |
| `commented` | コメントのみ | COMMENTED |

### 2.3 CI の結果

GitHub の結果（conclusion）を、**どの値でも出来事にし、値の名前をそのまま出す**（D-011、D-012）。本アプリで値を作ったり、まとめたり、訳したりしない。

| GitHub の値 | 意味（参考） |
| --- | --- |
| success | 成功 |
| failure | 失敗 |
| cancelled | 取り消し |
| timed_out | 時間切れ |
| skipped | スキップ |
| その他（action_required・neutral・stale・startup_failure など） | GitHub が返した名前のまま出す |

### 2.4 PR の状態

| コード | 業務語 | 定義 |
| --- | --- | --- |
| `open` | オープン | 開いている（下書きを除く） |
| `draft` | 下書き | 開いているが、下書き（Draft）のもの |
| `merged` | マージ済み | マージされて閉じた |
| `closed` | クローズ | マージされずに閉じた |

### 2.5 自分待ちの理由

PR が「自分待ち」になっている理由。1つの PR が複数の理由に当てはまることがある（例: 自分の PR で修正依頼と CI 失敗）。

| コード | 業務語 | 定義 |
| --- | --- | --- |
| `review_pending` | レビュー依頼に未対応 | 利用者へのレビュー依頼が GitHub 上で残っている（レビューすると消え、再依頼されると戻る）。チーム宛てのレビュー依頼も含める（S） |
| `changes_requested` | 修正依頼あり | 利用者が作った PR で、修正依頼を受けている |
| `ci_failed` | CI 失敗 | 利用者が作った PR で、CI が失敗している |
| `approved` | 承認済み（マージ待ち） | 利用者が作った PR で、承認されていてマージを待っている |
| `assigned` | アサイン | 利用者が担当者になっている |

`ci_failed` の「CI」は、GitHub が PR の画面に表示するチェックの総合結果（GitHub Actions 以外のチェックも含む）とする（D-012）。出来事の CI の結果（2.3）が「自分が起動した GitHub Actions」に限られるのとは範囲が違う。

## 3. PR の一覧で使う言葉

| 業務語 | 定義 |
| --- | --- |
| 自分に関わった PR | github-prs と同じ条件（`involves:@me`。利用者が作成者・担当者・メンションされた人・コメントした人のいずれか）に、利用者にレビュー依頼が来ている PR を加えたもの |
| 直近に関わった PR | 自分に関わった PR のうち、期間内に更新されたもの。closed・merged も含む。github-prs の一覧と同じ範囲。**PR の一覧はこの1つで、更新の新しい順に並べ、スクロールで全件を見る**（D-016） |
| 自分待ちの PR | 直近に関わった PR のうち、open（下書きを除く）で、自分待ちの理由（2.5）に1つ以上当てはまるもの。intent.md の「自分が対応すべき PR」と同じ。**別の一覧には分けず、PR の一覧の中で理由のラベルで示す**（D-016） |
| 参加中の PR | 利用者がレビュー・コメントした、他人が作った open の PR。出来事 `participating` の対象（2.1） |

- **期間**は既定7日で、利用者が1〜30日の範囲で変えられる。PR の一覧（自分待ちのラベルを含む）にかかる（D-010、D-012）
- **出来事の一覧の日数**は、期間とは別に利用者が選べる。範囲と既定は 1〜30日・既定7日（AI案）。立ち上がっていなかった間の出来事を遡る日数にも使う（D-016）
- 期間をかけるので、更新が止まったまま期間を過ぎたレビュー依頼は、PR の一覧から消え、自分待ちのラベルも見えなくなる。2026-11-26 時点では、レビュー依頼中の open の PR 14件のうち10件が7日以上更新されていなかった。依頼者はこれを知ったうえで、同じ期間をかけることを選んだ
- 「自分に関わった PR」にレビュー依頼を明示的に加えるのは、GitHub のドキュメントが `involves` の範囲を作成者・担当者・メンション・コメントとしていて、レビュー依頼を含めていないため。ただし 2026-11-26 時点の実データでは、レビュー依頼中の open の PR 14件はすべて `involves:@me` にも入っていた（出典: https://docs.github.com/en/search-github/searching-on-github/searching-issues-and-pull-requests ）

## 4. 用語の対応表

| 業務語（この案件で使う言葉） | GitHub の言葉 | 使い分け |
| --- | --- | --- |
| 出来事 | notification、event、timeline item など | 1件のコメント・レビュー・依頼の単位。GitHub の「通知」とは単位が違う |
| デスクトップ通知 | （OS の通知） | 本アプリが OS に出す通知。GitHub の「通知（notification）」と混同しないよう、**「通知」と単独では書かず**、どちらかを明記する |
| GitHub の通知受信箱 | Notifications inbox | GitHub の画面の通知一覧。本アプリとは既読をそろえない（D-007） |
| 出来事の一覧 | — | 本アプリの画面。受け取った出来事を表示する |
| 自分待ちの PR | — | 本アプリ独自の言葉（3.） |
| 参加中の PR | （participating） | GitHub の「参加中（participating）」は、作成者・メンション・アサインなども含む、より広い意味で使われる。本アプリでは 3. の狭い意味で使う |
| 直近に関わった PR | `involves:@me` ＋ `updated:` | github-prs と同じ範囲（3.） |
| レビュー依頼 | review request | |
| 修正依頼 | changes requested | |
| 承認 | approved | |
| アサイン | assign / assignee | |
| メンション | mention | |
| bot | Bot（アカウントの種類） | GitHub がアカウントの種類を Bot としているもの。普通のユーザーとして作られた bot アカウントは含まれない |
| CI | GitHub Actions のワークフロー実行（出来事）、PR のチェック（自分待ちの理由） | 出来事と自分待ちの理由で範囲が違う（2.3・2.5） |

## 5. 設計への申し送り

| 内容 | 引き継ぎ先 |
| --- | --- |
| 出来事は1件のコメント・レビュー・依頼の単位（D-011）。GitHub の通知受信箱の通知は PR・issue ごとに1件で、最新のコメントへのリンクしか持たない。1件ずつの出来事にするには、別の情報源と組み合わせる必要がある | ⑦ 取り込み元の決定、⑩.1 出来事の識別子 |
| 出来事は発生から5分以内に受け取る（intent.md S1） | ④ で粗い数値、⑨ で定量化 |
| 期間は PR の最終更新日時が基準。既定7日、利用者が1〜30日で変えられる | ⑩.3・⑩.4 |
| PR の一覧も出来事の一覧もページ送りはせず、スクロールで全件を見る。出来事は1日数件〜数十件なので、30日分だと数百件になりうる。表示の重さを確かめる | ⑩.4・⑨ |
