# モックアップ（要件確認用・使い捨て）

- 作成: 2026-11-26（⑤ 最終合意の前の確認用。D-015）
- 開き方: `index.html` をブラウザで開く（Mac なら `open docs/requirements/mockup/index.html`）。外部への通信はしない

## 位置づけ

- **画面に何が出て、どう動くか**を確かめるためのもの。⑤ で合意する前に、文書では見えにくい違和感を見つける
- **見た目（色・書体・余白）は仮**。見た目の決まりは設計の ⑨ で要否を判断し、⑪ の design-system.md で決める。実際の見えの良し悪しは実装中に実機で詰める
- **本番のコードの土台にはしない**。作り方（フレームワーク）は ⑧ で決める
- データはすべて架空。会社のリポジトリ名や PR の実データは入れない

## 確かめること

1. ~~出来事の一覧と PR の一覧を、タブで切り替える（A）か、左右に並べる（B）か~~ → 利用者が選べる（D-016）
2. ~~出来事の一覧に何日分を出すか~~ → PR の一覧の期間とは別に選べる（D-016）
3. ~~直近に関わった PR に、自分待ちの PR も重ねて出すか~~ → PR の一覧は1つにまとめ、自分待ちは理由のラベルで示す。更新の新しい順、ページ送りなし（D-016）
4. 出来事が1日数十件並んだときに、1行の情報量で読めるか
5. 「受け取れていない」表示や、閉じていた間の出来事の区切りの目立ち方
6. その他、触ってみて違和感があるところ

見つかったことは、要件の直しとして各成果物と decisions.md に記録する。前の工程で決めるべきだったものには手戻りタグを付ける。

## 右側の「デモ操作」でできること

- 出来事を起こす（種類を選ぶ）。デスクトップ通知を真似た表示が右上に出る
- 受け取れない状態にする（ネットワーク・認証切れ・利用制限）
- 閉じて、しばらくしてから立ち上げ直す（閉じていた間の出来事が区切り付きで出る）
- 新しい版の知らせを出す、初回起動の画面を見る
- PR の一覧の「すべてのリンクをコピー」で、一覧に出ている PR のリンクをまとめてコピーする（デモの記録に先頭の数件が出る）
- 画面の並べ方（A／B）と、優先度 S・C の印の表示を切り替える
