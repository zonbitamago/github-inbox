## 1. 依頼時の言葉（原文）

> SlackでGitHubからの通知を受け取っていたが、Slackが使えない状況となったため、GitHubからの通知を受け取るためのデスクトップアプリを作成したい。
> GitHubでの活動を素早くこなすために、以下のような機能が欲しい。
> - GitHubで自身に関わる活動を受け取り、表示する（https://docs.github.com/en/integrations/how-tos/slack/integrate-github-with-slack を使っていました）
> - 自身に関連するPRを一覧で確認できる。（https://github.com/zonbitamago/github-prs のイメージ）

---

## 2. 背景

- これまで GitHub の Slack 連携アプリ（GitHub app for Slack）で通知を受け取っていた
- Slack が使えなくなった。この状況は **恒久的**（Slack には戻らない前提）

---

## 3. 実際に反応して動いていた通知

選ばれたもの:

- **レビュー依頼**（自分、または自分のチーム宛て。定期リマインダーも含む）
- **自分の PR への反応**（レビュー＝承認・修正依頼、コメント、CI の結果）
- **メンション・アサイン**（PR・issue・コメントでの @自分、担当への割り当て）

選ばれなかったもの:

- リポジトリ全体の活動（チャンネル購読で流れていた、自分が関わらない PR 作成・マージ、issue、リリース、デプロイ）

AI 補足: 依頼文の「自身に関わる活動」は、上の3つ（Slack 連携でいう個人向け通知に近い範囲）を指していると読める。リポジトリ全体の活動を範囲に含めないかは ③ で確定する。

---

## 4. 困りごと（4つすべて該当）

| # | 困りごと | なぜ困るか |
| --- | --- | --- |
| P1 | 相手を待たせてしまう | レビュー依頼やメンションに気づくのが遅れ、他の人の作業を止めてしまう |
| P2 | 自分の PR が止まる | 自分の PR にレビューや CI 失敗があっても気づかず、マージまでの時間が延びる |
| P3 | 代わりの手段では埋もれる | GitHub の通知受信箱（Inbox）やメール通知は量が多く、大事なものが埋もれる・見に行く習慣がない |
| P4 | 自分待ちのものが分からない | 今、自分が対応すべき PR がどれかを一覧でつかめず、抜け漏れが不安 |

AI 補足: 「なぜ困るか」の文言は AI が選択肢として示したもので、依頼者はそれを選んだ。依頼者自身の言葉での補足は今のところない。

## 6. 気づいたあとの動き

- **両方ある**: 通知からすぐブラウザで GitHub の該当ページを開いて対応する場合と、通知は「ある」と知るだけにして区切りのよいときにまとめて処理する場合
- Slack 上でその場で返信・確認済みにする使い方は選ばれなかった

AI 補足: 「すぐ開く」と「後でまとめて処理する」の両方に応えるには、届いた通知が後から見返せる形で残っている必要がありそう（③ で検討）。

## 8. 参考にした既存の仕組み

### 8.1 GitHub app for Slack の個人向け通知（公式ドキュメントより）

- issue の担当者に割り当てられた
- PR のレビュー依頼
- PR・issue 本文・コメント・Discussion でのメンション
- デプロイのレビュー依頼
- PR レビュー依頼の定期リマインダー（曜日・時刻を指定。自分宛て／チーム宛てを選べる）

出典: https://docs.github.com/en/integrations/how-tos/slack/use-github-in-slack 、 https://docs.github.com/en/subscriptions-and-notifications/how-tos/managing-your-scheduled-reminders

### 8.2 github-prs（依頼者が以前作った Web アプリ）

- GitHub の Search API で `involves:@me is:pr updated:>7日前` を検索し、自分が直近1週間に関わった PR を一覧表示する
- 一覧の列: リポジトリ、PR 番号、状態（open / closed / merged）、タイトル、リンク（開く・コピー）、最終更新日時
- 検索語と状態での絞り込み、更新日時の降順で並べる
- React + TypeScript + Vite、GitHub Pages で公開。トークンは URL のクエリで渡す方式

## 10. 追加ヒアリング（2026-11-26、Gitify の試用後）

依頼者の言葉:

> Gitifyを使ってみましたが、やりたいことの印象が違いました。
> Gitifyはメニューバー常駐型ですが、そうではなく、デスクトップアプリとして立ち上げたまま、AltTabとかで簡単にそのアプリに移れるようにしたいです。

確認したこと:

- Gitify は使うのをやめる。比較の相手からも外す
- 「AltTab」は Mac の AltTab アプリのこと。Mac では AltTab アプリと標準の Cmd+Tab の両方で、Windows では標準の Alt+Tab で切り替え対象に出てほしい

反映先: intent.md 3.（アプリの形）・6.（採らない選択肢）、decisions.md D-006
