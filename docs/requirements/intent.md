## 1. なぜ作るか

GitHub の Slack 連携で受け取っていた「自分に関わる通知」が、Slack を使えなくなったこと（恒久的）で届かなくなった。その結果、次の4つの困りごとが起きている（hearing-memo.md 4.）。

- P1 レビュー依頼やメンションに気づくのが遅れ、相手を待たせてしまう
- P2 自分の PR へのレビューや CI 失敗に気づかず、自分の PR が止まる
- P3 GitHub の通知受信箱やメールでは量が多く、大事なものが埋もれる
- P4 今、自分が対応すべき PR がどれか一覧でつかめず、抜け漏れが不安

このアプリの目的は、**GitHub 上で自分に関わる出来事に数分以内に気づき、自分待ちのものを一覧でつかめるようにして、相手を待たせず、自分の PR も止めないこと**である。

## 3. アプリの形

- **普通のウィンドウを持つデスクトップアプリ**として、立ち上げたままにしておく
- 他のアプリで作業中でも、**OS のアプリ切り替えですぐこのアプリに移れる**こと
  - Mac: 標準の Cmd+Tab と、依頼者が使っている AltTab アプリの両方で切り替え対象に出る
  - Windows: 標準の Alt+Tab で切り替え対象に出る
- メニューバー（Mac）やタスクトレイ（Windows）のアイコンから開く常駐型にはしない

根拠: 依頼者が Gitify（メニューバー常駐型）を試し、「やりたいことの印象が違った」。立ち上げたまま Alt+Tab などで移れるアプリにしたい（hearing-memo.md 10.、D-006）。

## 4. 成功の合図

リリースの2〜4週間後の事後確認で、次の2つを 達成／未達／判断できない で判定する。

| # | 成功の合図 | 確かめ方（案） |
| --- | --- | --- |
| S1 | レビュー依頼・メンション・アサイン・自分の PR への反応（レビュー、コメント、CI の結果）が、**発生から5分以内に**デスクトップ通知で届く | 事後確認の期間中に、通知が届いた時刻と GitHub 上の発生時刻を数件突き合わせる |
| S2 | アプリの **1画面で「自分が対応すべき PR」が分かり**、GitHub を探し回らなくて済む | 依頼者の評価と、期間中に、自分待ちなのに PR の一覧で理由のラベルが付いていなかった PR が見つかった件数（acceptance.md 3.） |

- S1 の「5分」は、依頼者の「3〜5分以内に気づければ問題ない」に基づく
- S2 の「自分が対応すべき PR」は、business-data.md の「自分待ちの PR」と同じ（範囲は business-data.md 3.、D-010）
- 確かめ方の細部（何件突き合わせるか、誰がいつ見るか）は ④ で受け入れ条件に落とす
- 「3. アプリの形」が満たされているか（OS の切り替えで移れるか）は成功の合図ではなく、④ の受け入れ条件で確かめる

## 5. 何を成功としないか

| やらないこと | 根拠 |
| --- | --- |
| Slack 連携の機能を全部再現すること（リポジトリ全体の活動を流すチャンネル購読、スラッシュコマンドなど） | 反応して動いていたのは自分に関わる通知だけで、リポジトリ全体の活動は選ばれなかった（hearing-memo.md 3.） |
| アプリの中でレビュー・承認・コメントまで済ませること | 気づいた後の対応は GitHub の画面で行っており、その場で済ませる使い方は選ばれなかった（hearing-memo.md 6.） |
| チームの全員に導入・定着させること | チームの困りごとは人により違う。成功の合図にも選ばれなかった（D-005） |

上の範囲は ③ で Won't として改めて確定する。

## 6. 採らない選択肢と却下理由

| 選択肢 | 扱い | 理由 |
| --- | --- | --- |
| 何もしない（GitHub の通知受信箱・メール通知のまま） | 採らない | 量が多く大事なものが埋もれる。見に行く習慣もない（P3） |
| 他のチャットツールの GitHub 連携（Microsoft Teams の GitHub アプリなど） | 採らない | 社内で使えない |
| 既製品の Gitify（OSS の GitHub 通知デスクトップアプリ。Mac/Windows/Linux 対応） | 採らない（試したうえで使うのをやめた） | メニューバー常駐型で、立ち上げたまま OS の切り替えで移れるアプリという形（3.）と合わない。自分に関わる PR の一覧（P4）の機能もない（D-006） |
| GitHub Mobile（スマートフォンへのプッシュ通知） | **併用する**。自作の代わりにはしない | 併用はするが、作業中に見ている PC 側で気づける仕組みが別に必要（D-004） |
| GitHub Desktop の通知 | 採らない | 通知されるのは自分の PR へのレビューと CI 失敗だけで、レビュー依頼・メンション・アサインが届かない |
| 既存の github-prs（Web アプリ）を拡張する | 採らない | デスクトップ通知や配布の形が大きく違うため、新規リポジトリで作る（D-001）。検索の考え方と一覧表示は参考にする |

調べた出典:

- Gitify: https://github.com/gitify-app/gitify （2026-11-25 に v8.3.0。github.com で通知の表示・既読・完了・購読解除・絞り込みに対応）
- Teams の GitHub アプリ: https://docs.github.com/en/integrations/how-tos/teams/use-github-in-teams
- GitHub Desktop の通知: https://docs.github.com/ja/desktop/working-with-your-remote-repository-on-github-or-github-enterprise/configuring-notifications-in-github-desktop

## 7. この投資で何が変わるか

| | 現状 | あるべき姿 |
| --- | --- | --- |
| 気づく | 通知受信箱やメールに埋もれ、気づくのが遅れる | 自分に関わる出来事に、発生から5分以内にデスクトップ通知で気づく |
| 移る | GitHub の通知を見るには、ブラウザで通知受信箱やメールを開きに行く | 立ち上げたままのアプリに、OS の切り替え（Cmd+Tab・AltTab・Alt+Tab）ですぐ移れる |
| 対応する | 気づいた時点で探しに行くか、気づかないまま放置される | すぐ GitHub で開くことも、後でまとめて処理することもできる |
| 見渡す | 自分待ちの PR を GitHub で探し回る（github-prs は直近1週間に関わった PR の一覧のみ） | アプリの1画面で、自分が対応すべき PR が分かる |
